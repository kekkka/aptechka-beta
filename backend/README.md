# Бэкенд «Аптечки»

Spring Boot 4 (Java 25), PostgreSQL, схема через Liquibase (`src/main/resources/db/changelog`).
Аутентификация — stateless HTTP Basic по аккаунтам из таблицы `app_user`.

## Миграции

Схему ведёт Liquibase, Hibernate её только проверяет (`ddl-auto: validate`). Changelog запускается при старте приложения:
`db.changelog-master.yaml` подключает файлы из `changes/`. Новое изменение — новый файл `changes/NNN-что-меняем.yaml`
и строка `include` в master; уже применённые changeset'ы не правим. База, созданная прежней Flyway-миграцией, подхватывается
без пересоздания: changeset'ы начальной схемы отмечаются выполненными, если таблица уже есть (таблицу `flyway_schema_history`
после этого можно удалить).

## Запуск

```bash
docker compose up --build          # из корня репозитория: Postgres + бэкенд + фронтенд
./gradlew bootRun                  # локально, Postgres на localhost:5432 (DB_URL, DB_USERNAME, DB_PASSWORD)
./gradlew test                     # тесты на H2, без Docker
```

`APP_TIMEZONE` (по умолчанию `Europe/Moscow`) — часовой пояс подопечного: время приёма — это его местное время.

## Роли в круге заботы

| Роль | Что может |
|---|---|
| `OWNER` — организатор | всё: профиль, круг заботы, назначения, пороги показателей |
| `CAREGIVER` — сиделка | отмечать приёмы, вести аптечку и дневник здоровья, откликаться на просьбы о помощи |
| `FAMILY` — родственник | смотреть план, здоровье и сигналы, откликаться на просьбы о помощи |
| `PATIENT` — подопечный | свои приёмы, «Мне плохо», самочувствие и давление |

Чужой профиль отдаёт 404, недостающее право — 403. Ошибки приходят в формате ProblemDetail (`detail` — текст для пользователя).

## API

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register` | регистрация (без авторизации) |
| `GET /api/me` | аккаунт и профили, к которым есть доступ; заодно проверка логина |
| `POST /api/patients`, `GET/PUT /api/patients/{id}` | профиль подопечного; создатель становится организатором |
| `GET/POST /api/patients/{id}/members`, `PUT/DELETE …/members/{memberId}` | круг заботы: добавить зарегистрированного человека по почте с ролью |
| `GET/POST …/courses`, `POST …/courses/{courseId}/end` | назначения: ежедневные схемы до 90 дней, до 8 времён в день |
| `GET …/schedule?date=` | приёмы на день со статусами `TAKEN`, `SKIPPED`, `PLANNED`, `DUE`, `OVERDUE` |
| `POST …/doses`, `DELETE …/doses/{logId}` | отметка приёма (списывает остаток из аптечки) и её отмена |
| `GET/POST …/stock`, `PUT/DELETE …/stock/{itemId}` | аптечка; повторная упаковка того же препарата пополняет запись |
| `POST …/stock/scan` | штрихкод или DataMatrix «Честного знака» → GTIN, серия, срок годности и что о препарате уже известно |
| `GET …/shopping` | что докупить на оставшиеся приёмы активных курсов |
| `GET/POST …/vitals`, `GET …/vital-thresholds`, `PUT/DELETE …/vital-thresholds/{type}` | дневник здоровья и пороги, при выходе за которые появляется сигнал |
| `POST …/help-requests`, `POST …/help-requests/{id}/resolve` | «Мне плохо» от подопечного и отклик семьи |
| `GET …/signals`, `GET …/summary` | сигналы семье и сводка для главного экрана |

## Что ещё не сделано

- Push-уведомления: сигналы пока вычисляются при запросе, фронтенд опрашивает сервер каждые 30 секунд.
- Приглашение по почте: человек сначала регистрируется, потом организатор добавляет его.
- Справочник препаратов по GTIN (`drug_catalog`) пуст — его нужно наполнить из ГРЛС или «Честного знака».
  Пока неизвестная упаковка заполняется вручную один раз, дальше аптечка узнаёт её по штрихкоду.
- Интеграция с аптеками и Купером для покупки по списку.
