# Аптечка · Beta

Мобильный прототип для семейной заботы о лечении близкого. Пациент видит ближайшее лекарство и отмечает приём свайпом, сиделка помогает с расписанием, а менеджер лечения управляет назначениями и домашним запасом.

Приложение написано на **React 19 + TypeScript + Vite**. Данные хранятся в браузере; распознавание фото и PDF выполняется локально.

## Быстрый запуск

Требуются **Node.js 22.12+** и **pnpm 11.25.0**. В GitHub Actions используется Node.js 22.

```bash
# Если pnpm ещё не установлен
npm install --global pnpm@11.25.0

pnpm install --frozen-lockfile
pnpm dev
```

Открыть [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Сервер привязан к локальному интерфейсу; если порт занят, Vite сообщит об этом.

Также можно запустить `./start-local.sh`: скрипт использует системный Node.js или установленный на этом компьютере runtime Codex. Зависимости нужно установить заранее.

## Вход и роли

Вход — выбор аккаунта одним нажатием, без логина и пароля. Кнопка профиля возвращает к выбору; после перезагрузки аккаунт нужно выбрать снова. Смена роли сохраняет данные лечения.

| Аккаунт | Роль | Основные возможности |
| --- | --- | --- |
| Нина Петровна | Пациент | Барабан лекарств, отметка приёма, связь с близкими, история для врача |
| Елена | Сиделка | Просмотр плана, отметки приёмов, работа с сигналами и журналом |
| Анна | Менеджер лечения | Импорт назначений, управление курсами, запасом и доступом помощников |

Это демонстрационные роли одного браузера, а не серверная авторизация. Импортированное назначение доступно пациенту, менеджеру и выбранному помощнику; права помощников настраивает менеджер.

## Сценарий пациента

На главном экране остаются барабан лекарств и две крупные кнопки. Нижней навигации у пациента нет.

1. **До назначенного времени** карточка показывает «Пока не принимайте», точное время и ожидание.
2. **В течение часа после назначенного времени** доступен свайп слева направо. Короткий свайп возвращается назад; завершённый сразу сохраняет отметку без дополнительного окна.
3. **После отметки** появляется подтверждение с галочкой, затем карточки прокручиваются вверх. Принятое лекарство остаётся сверху с зачёркнутым названием.
4. **Через 60 минут без отметки** приём получает статус «Не принято», становится красным и уступает место следующему приёму дня. Запас при автоматическом пропуске не списывается.

Окно считается по времени расписания: для приёма в 13:00 отметка доступна с 13:00 до 13:59 включительно; в 14:00 окно закрывается. Отложенное напоминание не продлевает его.

**«Позвонить близким»** открывает список контактов. Телефония пока демонстрационная: реальный звонок не выполняется.

### «Показать врачу»

Отдельная страница `#doctor` показывает:

- историю за сегодня, 7 или 30 дней;
- сводку принятых лекарств, пропусков и отсутствующих данных;
- просмотр по дням или по препаратам;
- название, форму, дозировку, количество и время приёма;
- автора, время, основание отметки и комментарий;
- фильтры подтверждённых приёмов и пропусков.

За прошлые дни без записей показано **«Нет данных»**. Отсутствие отметки не считается доказанным фактом пропуска. Страница предназначена для просмотра и не меняет назначения или отметки.

Раздел **«Показатели здоровья»** содержит демонстрационные графики давления, пульса и самочувствия. Они переключаются вместе с периодом отчёта; по нажатию или стрелками клавиатуры можно выбрать точку. Все значения вымышлены и помечены как примеры. Реальные измерения ещё не подключены.

## Как пользоваться демо-временем

Кнопка **«Демо · ЧЧ:ММ»** в шапке открывает шкалу дня.

1. Передвиньте шкалу. Пока не нажата кнопка, меняется только предварительный выбор.
2. Нажмите **«Перейти»**, чтобы применить время.
3. Сделанные отметки, запас и история сохраняются при перемотке вперёд и назад. При движении за конец часового окна неотмеченный приём автоматически становится пропущенным.
4. Чтобы повторить отдельный приём, вернитесь в его часовое окно. В этом же меню нажмите **«Сбросить»** у нужного препарата.

Явный сброс очищает только выбранный приём, его сигналы и связанные записи журнала; списанный при отметке запас возвращается один раз. Остальные приёмы и назначения не сбрасываются. Вне часового окна сброс недоступен.

Часы и дата в прототипе демонстрационные. Время не синхронизируется с системными часами; сохранённая дата демо может отличаться от календарной даты устройства.

## Назначения, распознавание и аптечка

Менеджер может загрузить фото/PDF, сфотографировать документ, вставить текст или внести назначение вручную.

Флоу: **документ → проверка каждого препарата → сверка домашнего запаса → запуск плана**.

- Печатный русский и английский текст распознаёт Tesseract.js.
- Текстовые PDF читает PDF.js; для сканов применяется OCR.
- Кнопка «Распознать пример» создаёт учебное изображение и действительно запускает OCR.
- Оригинал и распознанный текст доступны для сверки; поля можно исправить и разобрать текст повторно.
- Каждый препарат требует подтверждения. Неуказанные поля не подставляются автоматически.
- Учитываются отдельная длительность препаратов, форма, дозировка, остаток и срок годности.
- Список покупок рассчитывается на оставшийся курс; подтверждённый приём уменьшает запас.
- Журнал сохраняет автора и основание отметки; сигналы помогают проверить отсутствие подтверждения.

### Ограничения импорта

До **6 файлов**, **10 страниц**, **10 МБ на файл** и **30 МБ суммарно**. Поддерживаются постоянные ежедневные схемы таблеток/капсул: до **90 дней**, **8 препаратов** и **8 времён приёма** на препарат.

Сложные, переменные и схемы «по необходимости» автоматически не запускаются. Качество распознавания рукописи не гарантируется. Результат OCR необходимо сверить с оригиналом назначения.

## Хранение и ограничения прототипа

Состояние хранится в `localStorage` под ключом `aptechka_family_mobile_v1`. Формат совместим с предыдущей версией прототипа. Очистка данных сайта удалит сохранённые назначения, остатки и журнал.

Фото, PDF и распознанный текст обрабатываются в памяти вкладки и не отправляются в OCR/API. После импорта сохраняется проверенный план. Библиотеки, шрифты и языковые модели включены в `public/vendor/` и копируются в сборку.

Пока отсутствуют:

- серверная авторизация и синхронизация между устройствами;
- настоящие push/SMS, телефонные звонки и приглашения помощников;
- интеграции устройств и реальные измерения показателей;
- медицинская валидация и защищённое медицинское хранилище.

Названия и упаковки встроенных демо-препаратов взяты из каталога МДЛП. Назначения, расписание и события демонстрационные. Для демонстрации используйте обезличенные документы. Прототип не заменяет назначение врача; отметка человека не является объективным подтверждением приёма.

## GitHub Pages

При push в `main` workflow:

1. устанавливает Node.js 22 и pnpm 11.25.0;

## Домашняя аптечка и каталог

Экран «Домашняя аптечка» (`#stock`) сохраняет вкладки «Дома» и «Купить»: поиск по запасам, остатки и сроки годности, редактирование партий и расчёт покупок. Кнопка добавления и «Пополнить аптечку» открывают поиск в каталоге МДЛП. После сохранения новые партии появляются дома, а покупки пересчитываются автоматически. Менеджер редактирует запасы, сиделка просматривает их.

«Добавить лекарство» открывает поиск в реальном открытом каталоге МДЛП: по торговому названию, МНН, цифровому штрихкоду, номеру регистрационного удостоверения (РУ) из реестра или камерой (EAN/UPC, GTIN и GS1 Data Matrix). Новые позиции выбираются только из каталога; при отсутствии совпадения произвольная карточка не создаётся. Встроенное демо использует реальные позиции каталога: Эналаприл 10 мг, Амлодипин 5 мг и Омепразол 20 мг. Расписание остаётся учебным и не является назначением. Старые встроенные «Препарат А/Б/В» обновляются без сброса остатков, отметок и времени; пользовательские назначения не меняются.

После выбора конкретной упаковки указываются количество и срок годности. Упаковки пересчитываются только при однозначно известном содержимом; иначе вводится остаток в указанной единице. Каждое пополнение создаёт отдельную партию. Приём списывает пригодный запас с ближайшим сроком годности; отмена и сброс возвращают его в исходные партии. Старые записи запаса и отметок поддерживаются без сброса localStorage.

Камера требует HTTPS или localhost и разрешения браузера. При недоступной камере можно ввести код цифрами. Распознавание работает на устройстве; поиск выполняется в Web Worker по локальному снимку, без отправки поисковых запросов и истории пациента поставщику каталога.

### Обновление каталога

Источник: [открытые данные МДЛП «Честного знака»](https://датамаркет.честныйзнак.рф/bi/opendata/7731376812-MDLPGtins). Дата снимка, исходная ссылка и количество записей находятся в `public/catalog/metadata.json`. В комплекте — 69 771 товарная позиция со статусом «Действующий» из выгрузки 29 октября 2026 года. Каталог загружается только при открытии добавления, его размер около 26 МБ до сжатия.

Обновление выполняется отдельно от сборки (Python 3, без дополнительных библиотек):

```bash
python3 scripts/prepare-catalog.py
# Воспроизводимая подготовка из определённой версии:
python3 scripts/prepare-catalog.py --url 'https://xn--80aaani3am7aog.xn--80ajghhoc2aj1c8b.xn--p1ai/bi/api/opendata/7731376812-MDLPGtins/data/data-20261029-structure-20240611.csv' --date 2026-10-29
# Или из сохранённого CSV:
python3 scripts/prepare-catalog.py --input /path/to/catalog.csv --date YYYY-MM-DD
```

Проверяйте diff снимка и метаданных перед публикацией. Сборка не обращается к источнику. Файлы каталога и worker используют относительные пути для размещения на GitHub Pages.

Нажатие на препарат во вкладке «Дома» открывает нижнюю панель с данными запаса и информацией об упаковке из каталога МДЛП (МНН, производитель, упаковка, РУ, GTIN). Карандаш отдельно открывает редактирование. Для старых записей без идентификатора каталога отображаются только сохранённые данные.


## Дополнительные сведения ГРЛС

МДЛП и ГРЛС используются совместно: МДЛП определяет конкретную упаковку, её GTIN, дозировку и форму, а ГРЛС добавляет регистрационные сведения по точному нормализованному номеру РУ. Это сохраняет сканирование и не требует извлекать дозировку из длинного описания нескольких форм выпуска в Excel. Каталог добавления в этой версии не расширяется записями, которые есть только в ГРЛС.

В нижней панели препарата доступны фармакотерапевтическая группа, держатель РУ и его страна, даты регистрации и окончания действия, статус записи и известное значение признака ЖНВЛП. Производитель упаковки из МДЛП и держатель РУ из ГРЛС показаны отдельно. Стадии производства и названия нормативных документов раскрываются в «Производство и документы». Дата окончания РУ не является сроком годности партии.

ГРЛС загружается только при открытии информации о связанном препарате и обрабатывается в Web Worker. Обычный поиск и сканирование этот файл не скачивают. Если совпадения нет или источник не загрузился, сведения МДЛП остаются доступны. Повтор загрузки ГРЛС не скрывает упаковку и не меняет запас, назначения или отметки пациента. Различающиеся записи с одним РУ отображаются вариантами. Пустые значения и `~` не интерпретируются как «Нет».

### Подготовка выгрузки ГРЛС

Требуются Python 3 и `openpyxl` (можно установить в отдельное окружение: `python3 -m pip install openpyxl`). Скрипт читает исходники, не изменяя Excel:

```bash
python3 scripts/prepare-grls.py '/Users/dblarin/Downloads/grls2026-10-30-1'
# Другой каталог результата или другой снимок МДЛП для сверки:
python3 scripts/prepare-grls.py /path/to/export --output-dir public/catalog --mdlp public/catalog/medications.json
```

Используются ровно четыре файла с одинаковой датой снимка: «Действующий», «Выдано по правилам ЕАЭС», «Действует в иностранных упаковках», «Действует на подтверждении государственной регистрации». Исторические, исключённые, истёкшие и приостановленные записи не подключены. Неверная структура, отсутствие обязательного файла или разные даты останавливают импорт до записи результата.

Результат — `public/catalog/grls.json`, сгруппированный по РУ, и `grls-metadata.json` с исходными именами файлов, SHA-256, датой и статистикой сопоставления. На снимке от 30.10.2026: 29 363 исходные строки, 29 304 нормализованных РУ, 29 350 вариантов после удаления точных дублей; у 37 РУ остаются разные варианты. Совпадение найдено для 64 828 из 69 771 упаковки МДЛП. Строгая нормализация сохраняет значимые буквы и ведущие нули. Размер JSON ГРЛС — около 25 МБ до сжатия; данные не дублируются для каждой упаковки.

Обычная production-сборка использует подготовленные JSON и не читает Excel, не требует Python и не обращается к реестрам. Пути поддерживают GitHub Pages и размещение во вложенном каталоге. Импорт проверяется отдельно:

```bash
python3 -m unittest discover -s tests -p 'test_prepare_grls.py'
```

Сведения о регистрации не являются полной инструкцией: эта Excel-выгрузка не добавляет показания, противопоказания и правила приёма. «Нормативная документация» содержит названия документов, а не их текст.

Прямую загрузку инструкций с сайта ГРЛС подтвердить не удалось; источник PDF обозначен как производитель, регистрационные сведения отдельно взяты из снимка ГРЛС. Дата проверки не является датой утверждения инструкции.

Сопоставление строгое: РУ, торговое название, дозировка и форма. На другого производителя или другую дозировку описание не переносится. У других препаратов остаются сведения реестров. Инструкции не выгружаются автоматически и не обновляются при сборке; при изменении РУ или инструкции требуется повторная проверка редактором. Полные перечни противопоказаний, взаимодействий и реакций доступны по ссылке на оригинал; краткий пересказ не задаёт персональную дозировку.

Обновление демо меняет только нетронутые встроенные препараты и исходные партии `sa`/`sb`, сохраняет их количество, сроки, журнал и расписание. Добавленные пользователем партии других производителей не переименовываются.
